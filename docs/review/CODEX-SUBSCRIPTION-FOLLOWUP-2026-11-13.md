## 配置与实现

新增可选配置 `config.codex.yaml`，明确设置 `provider: codex`、`billing: subscription`，
三个模型档位均为 `gpt-6.1-sol`。原 `config.yaml` 仍使用 Claude，没有改写默认配置或账户登录。
`get_provider` 在 Codex 模式下拒绝 API key 与 API 计费配置；CLI 强制使用 ChatGPT 登录。
此模式用于用户本机开发，不用于向其他用户提供共享订阅的托管服务。

新增 `CodexCLIProvider` 调用 `codex exec`，用 JSONL 读取答案、失败状态和实际 token 统计。
输入通过 stdin 传入；运行目录是独立临时空目录。进程忽略个人 Codex 配置、不加载项目
AGENTS 内容，关闭原生命令执行、网络搜索、apps、图片读取及代理委派，并检查输出中
是否出现意外原生工具调用。凭据由已登录的 Codex CLI 管理，没有复制、打印或保存到项目。

研究仍由 RegLens 的已有程序循环控制：模型输出 JSON 工具请求，程序通过相同的工具契约
验证并执行 `Toolbox`，最后复用原有引用解析、全文交付检查、结构验证、路由和评测清单。
这与 Claude CLI 的原生 MCP 编排存在差异；不是只替换模型、其他变量完全相同的对照试验。
默认工具预算 10 次、13 个模型回合，沿用 200,000 tokens 的请求前预算检查及最终回答预留。
最后一次响应仍可能超过预留量，不能将此预估检查称为绝对硬 token 上限。

`input_tokens` 中的 `cached_input_tokens` 是子集，记账会先扣除再单列缓存，避免重复计数。
不为 Codex 模型猜测 API 价格：调用账目中的 `cost_eur` 为 null，而非“实际费用为零”。
既有 EUR 汇总仅累计有定价的项目，不能用其缺少的 Codex 金额推断免费。
缓存命名空间包含 provider 和 billing，且对适配器源码做指纹，历史 Claude 答案不会充当
新的 Codex 生成结果。评分器也使用 Codex，并沿用冻结参考及原评分提示版本 `75d32dd9`。

官方依据：[CLI 命令与登录](https://learn.chatgpt.com/docs/developer-commands)、
[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。本次另实际执行
`codex login status`，结果为 `Logged in using ChatGPT`，随后小型模型请求成功。
