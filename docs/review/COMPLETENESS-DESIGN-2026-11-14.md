# Bounded scope and requested-list coverage

Personal project; not legal or regulatory advice.

The existing guard only independently probes quoted definitions and explicit paragraph ranges.
The saved app-004 scope gap is incorrectly treated as unavailable. Other saved answers omit
children of a list introduction or items already delivered inside a paragraph.

Implementation decision: extend deterministic evidence planning and the shared guard, using the
existing answer requirements and missing-requirements fields. A prompt-only change would still
depend entirely on self-reporting. A separate semantic judge would add model calls to every answer.
Neither is needed for these structural signals.

Scope candidates come from indexed scope/addressee headings in an unambiguously question-matched
source, never from the registry applicability label. Requested-list candidates come from the same
article or a narrowly shared section, with question-term relevance. Resolve complete logical units,
apply every caller filter, and share the existing four-row/12,000-character expansion budget.
Bound probes to four anchors, 40 candidates per anchor and eight target units; never infer legal
absence from an empty probe. Omitted available units become specific guard requirements.

For enumerated passages actually delivered, flag items whose distinctive vocabulary is entirely
absent from the answer/claims. This is a conservative request to review coverage, not semantic
entailment, a legal conclusion or a completeness certificate. Do not use checklist prose itself
as proof of answer coverage. Restrict the signal to requested lists and indispensable conditions;
optional background and missing user inputs must remain free of automatic research.

The single-pass guard, API/Codex pre-final check and all agent post-resolution checks use the same
planner. Agent evidence includes every traced delivered window, even if not finally cited.
Keep C# resolution separate from corpus-key evidence. Preserve all existing model/tool budgets.
